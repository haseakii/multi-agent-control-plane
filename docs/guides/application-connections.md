# 应用接入与成员安装

打开工作台顶部“接入应用”，选择客户端、勾选一个或多个项目，再选“发任务与继续追问”或“只查看”。页面直接展示各项目工作目录和授权范围，不需要填写启动路径。

同一个客户端只安装一次。之后在已有接入点击“管理项目”，勾选或取消项目再保存，配置、凭据和 MCP 名称保持不变；下一次调用按新范围校验。已有 local_collaboration 也可直接管理项目，无需新增配置项。修改工具权限后，如果客户端仍缓存旧列表，刷新工具列表或重连一次。只读接入的新 MCP 工具列表仅展示查看操作，后台仍逐次校验调用。

- Codex：点击“安装到 Codex”。工作台通过已安装的 Codex CLI 新增独立 MCP 项；原配置先留副本，不覆盖原 local_collaboration。随后在客户端重连。客户端配置写入不等于连接成功，第一次实际调用才显示调用记录。
- Cursor、VS Code：点击安装链接，在客户端确认安装。如果浏览器未打开客户端，可复制完整 JSON。
- IDEA：在 AI Assistant 的 MCP 页面添加并粘贴完整配置，再应用。其他本机 MCP 客户端可使用通用 JSON。

每个接入有独立凭据，只授权选中的项目。凭据留在安装目录的私有连接文件中，复制出来的 JSON 只包含本机固定入口与连接文件引用。升级复用入口和连接文件。此方式用于同一台电脑，不适用于把本机路径复制到远程主机。

“撤销授权”会立即阻止此凭据的后续受控调用，任务、附件、上下文和代码改动保留。已撤销记录不占用 64 个有效接入名额。已发起的任务不会因此被取消。撤销范围是协作 MCP 网关，不是对同一 Windows 用户所有本机进程的隔离。需要恢复授权时新建独立接入。

新成员在“协作成员”的产品目录安装。选择产品后，页面展示固定版本、来源和校验方式，点击“确认安装并接入”。支持本平台 Windows ZIP 和带精确版本的 npm 适配器；不支持的产品可使用本机已有入口。程序放在安装目录的 agents 下，每次失败保留原件，重试使用独立尝试目录，不覆盖旧成员。目录提供 SHA-256 时验证后才解压；目录没有校验和时明确显示仅 HTTPS 来源验证。npm 使用随发布包携带的本机 Node 发行版 npm，禁用安装脚本，不执行全局安装。下载与安装继承工作台网络设置。

下载、安装、连接检查各有状态；后台中断会显示可重试，不能显示安装成功。程序安装后保存本机入口清单，已安装成员重试连接不再依赖目录缓存或联网；旧安装记录有原成员时可恢复入口，首次下载仍需确认当前目录来源。成功后打开成员，通过它自己的 ACP 登录入口授权，不复制其他成员的凭据，也不发送模型提示。新成员默认是普通协作者，未自动赋予负责人角色。

同一个 ACP 可以创建多位成员。在已接入成员卡，或已有安装记录中点击“使用现有程序创建成员”，填写名称并创建，程序会复用已有入口并检查连接，不重复下载。每位成员有独立 ID，可分别设置模型和网络代理。账号仍由 ACP 自己管理，复用同一程序时可能共享其默认登录，这不是提供商账号隔离；工作台不复制凭据或原成员的负责人权限。

MCP 客户端权限、ACP 成员登录和项目审批策略是独立的。现有工作区自动审批、命令确认和人工审阅合并保持原规则。LocalRunner 与 Git 工作树仍不是操作系统安全沙箱。
