# 启动、升级和恢复

## 日常使用

- 普通用户下载一个 **Hermes-Workbench-…-windows-x64.exe**，直接双击；无需解压或安装系统 Node。首次自动安装并打开网页，随后可使用开始菜单的 **Hermes 工作台** 或安装目录的 **工作台.exe**。程序自带配套运行时，Windows 10/11 x64 使用内置 .NET Framework 4.8。
- 打开新版 EXE，空闲时自动执行已有升级流程；有任务或成员安装未结束时暂缓升级，先打开当前工作台，稍后重开新版继续。旧 EXE 不会自动替换较新的安装。
- 双击 **启动工作台.cmd**。服务在后台运行，已有实例会复用，启动窗口可以关闭。Codex 的现有 MCP 入口仍可按需启动同一个服务。
- 升级时双击 **升级工作台.cmd**，选择已解压的新版目录。程序核对完整包、正常停机、创建备份、在新目录恢复并验证数据，再启动新版。无需编辑脚本或 Codex 配置。
- 如果升级失败，程序会尝试恢复原版本入口并保留原数据、备份和错误记录。若维护进程异常退出，可双击 **恢复工作台.cmd**；日常启动也会检查并恢复已确认退出的维护操作。
- **停止工作台.cmd** 正常停机，**工作台状态.cmd** 显示后台和维护状态。有任务正在执行或等待授权时，升级会提示先处理任务，当前任务与实例继续保留。

升级时网页历史可读，新写操作暂停受理，验证完成后恢复。命令、越界访问和人工审阅合并仍按既有权限处理。升级不会批准任务或合并代码。

已经运行的旧 MCP 进程需重连后才能加载客户端代码修复；连接配置保持原样。本次修复前的旧进程按用户选择留待稍后重连，新的 stdio 入口已验证停机后自动启动。

## 完整包首次运行

EXE 内置完整目录包，首次校验并展开到 `%LOCALAPPDATA%\MultiAgentControlPlaneCache`，安装与数据默认位于 `%LOCALAPPDATA%\MultiAgentControlPlane`。新安装自动避开占用端口；已有安装保留地址。程序缓存损坏时保留原件并从 EXE 准备新副本，不移动正在使用的目录，也不替换用户数据。多个启动操作互斥，重复打开复用同一个后台进程。当前 EXE 未签名，Windows 可能提示未知发布者；完整性校验不能代替发布者代码签名。

Windows x64 完整发布包带配套 Node/npm、网页、依赖和统一入口。双击包内 **打开工作台.cmd**，默认准备 `%LOCALAPPDATA%\MultiAgentControlPlane` 后打开工作台；以后使用该安装目录的中文快捷入口。控制台不需要系统 Node。“协作成员 → 添加 / 下载 ACP”支持隔离下载、重试及本机入口；账号登录由成员自身管理。成员子进程优先使用包内 Node/npm，并继承 Windows 的 APPDATA、LOCALAPPDATA，避免混用旧 nvm/npm。

安装包须从 ZIP 完整解压到新目录。如果提示 `Unexpected release file: data/...`，该副本中已混入运行数据：保留整个原目录，再从原 ZIP 解压一份新的安装包，不要直接删除 `data`。已有文件但没有完整安装记录的目标目录也会保留；可通过 `打开工作台.cmd --directory "新的空安装目录"` 明确选择其他位置。`--headless` 可只启动后台。

新版也可从已安装工作台的升级入口选择；包内 **升级工作台.cmd** 可显式升级默认安装目录。EXE 和新版包的 **打开工作台.cmd** 自动检查版本先后；再次打开较旧包不会自动降级。原 `start.cmd` 保留维护命令兼容。

原来通过 `start.cmd` 使用旧包 `data` 的用户，应先等任务结束并正常停止旧服务。保留整个旧目录，在新包中使用 `打开工作台.cmd --directory "新的空安装目录" --config "旧包目录\config.json"` 接管原数据。旧任务工作目录仍可能引用旧包路径，不能删除旧目录。前台与安装模式均提供 MCP 接入和 ACP 下载管理；前台 MCP 客户端需要服务保持运行。

## 发布入口（开发人员）

构建机器已有锁定依赖和已准备的 Hermes 源码时，从项目根运行：

```powershell
node scripts/publish.mjs --output release/new-version
```

统一完成 TypeScript 编译、完整本地测试、Hermes 类型检查与网页构建、Windows 完整打包、原生依赖及迁移探针、逐文件完整性验证，并构建旁边的 **new-version.exe**。构建机需要 Windows 自带的 .NET Framework C# 编译器；使用者无需编译器。输出必须是新的；程序不下载或安装构建工具。已有本轮验证过的网页构建可显式传 `--web-dist`，服务端仍重新编译、测试和打包。验证报告放在包旁的 `*-validation`，不混入包或用户数据，也不自动上传公开发布站点。

发布流程还运行 Hermes 浏览器回归，覆盖设置读取、运行中查看、MCP 配置、安装记录及阅读草稿；测试成员与安装器均隔离，不下载外部 ACP 或调用模型。成品另复制到含中文和空格的目录，通过实际 CMD 验证配套 npm/npx、首装、重复打开、空库与正常停止。证据分别保存在验证目录的 `hermes-usability` 和 `first-install` 中。

EXE 另有 `single-executable` 门禁：只复制一个 EXE，在移除系统 Node 路径并注入无效 Node 启动钩子的环境中验证首装、自动选择端口、并发复用、固定入口和缓存恢复；全部使用隔离目录。可用 `verify-windows-executable.mjs --executable 新版.exe --evidence 新目录 --previous 旧版完整目录` 额外验证跨版本升级。更多命令如 `工作台.exe --headless`、`工作台.exe --stop --headless` 可用于命令行；指定安装目录使用 `--directory`，测试或自定义缓存使用 `--cache`。

本机日用安装现位于仓库 `.data/control-plane`。以后发布新包，再执行：

```powershell
.\升级工作台.cmd --release "D:\path\to\new-package"
```

初次部署到指定目录可用随包 Node 调用 `launcher/control-plane.mjs install --release <完整包> --directory <新的私有安装目录>`；默认首次入口已封装这一步。已有配置的受控接管可附带 `--config` 和已有 `--connection`，不创建或扩大客户端授权。

## 数据与恢复边界

安装目录的 `installation.json` 是唯一当前版本选择。固定启动器、后台入口和 MCP 都解析它；程序副本保存在 `versions`，每次升级的数据副本保存在 `generations`，一致备份保存在 `backups`。连接文件与独立客户端授权继续使用原件，Agent 登录仅引用已有自管目录。

成功前，原数据代次不改写；新版只在恢复副本上应用兼容迁移。历史任务、输入附件 BLOB、结果产物和权限由同一备份恢复。已有工作树按原绝对路径继续使用，不复制或合并源项目。旧目录可能仍被这些记录引用，清理须使用工作区维护流程，不能直接删旧代次或历史 `.run` 数据。

自动回退只适用于尚未开放写操作的失败升级。一次升级已成功开放后，不把旧数据库当成通用“撤销”按钮，以免丢失新任务；未完成的已验证提交在恢复时继续完成。无法确认实例退出、锁身份或恢复结果时保留记录，显示恢复入口；不杀占用进程、不直接删除 `instance.lock`、不让旧程序打开新数据库。

第一次接管旧启动器是一次受控迁移，需保持空闲；后续升级走统一维护闸门。恢复不重放模型任务，也不改变自动审批范围。LocalRunner 和工作树仍不是操作系统沙箱。
