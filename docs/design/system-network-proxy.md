# 系统设置与每成员网络代理

状态：2026-10-25 已实现并完成隔离实机验证。当前支持无认证的 HTTP/HTTPS 代理；SOCKS、PAC 和代理凭据存储尚未实现。初始值为“保留原有设置”，升级不会自动替换日常网络配置。

## 入口与操作

顶部“系统设置”进入“网络代理”。菜单只展示已经实现的分类；不要求编辑启动命令或 JSON。成员抽屉中的“网络”摘要和任务诊断中的网络入口，均打开同一个设置弹窗并定位成员。关闭后返回原位置，输入草稿和成员抽屉保留。

先设置全局连接方式，再处理成员例外。地址允许输入 `127.0.0.1:7897`，界面明确显示规范化的 `http://127.0.0.1:7897`。地址中不允许用户名、密码、路径和查询参数。代理模式才显示地址及折叠的额外绕过规则，不预放尚未支持的选项。

| 层级 | 选择                     | 含义                                                   |
| ---- | ------------------------ | ------------------------------------------------------ |
| 全局 | 保留原有设置（初始默认） | 保留升级前行为，不读取或修改宿主、Windows 或浏览器代理 |
| 全局 | 直接连接                 | 工作台自有联网直连，向跟随者明确传入直连环境           |
| 全局 | 使用代理                 | 工作台自有联网与跟随者采用此地址                       |
| 成员 | 跟随全局（默认）         | 显示解析后的连接方式与来源                             |
| 成员 | 直接连接                 | 覆盖全局代理                                           |
| 成员 | 单独设置代理             | 使用独立地址及绕过规则，不受全局修改影响               |

优先级为成员明确选择、全局设置、原有行为。切换模式保留输入的地址，但仅解析当前启用的模式。模型、思考等级、常用方案仍在原运行设置中，和网络设置分别保存。代理覆盖控制平面启动的 ACP，不管理 Codex 客户端本身的联网。

## 保存、测试与返回

全局和全部成员例外是一份草稿，底部操作栏固定可见，一次原子保存。未保存关闭时可继续编辑或放弃。保存不会重启成员、打断任务或刷新登录状态；工作台后续联网立即采用新值，成员在下次启动时采用新值。

版本冲突保留原草稿及原基准，先读取最新版本并展示差异，再由用户选择载入最新或重新保存自己的草稿。回执丢失可点击“核对保存结果”；相同内容确认已有结果，不额外递增版本，也不静默覆盖另一窗口。

“测试此连接”使用未保存草稿，固定访问官方 ACP 目录服务，不接受任意目标，不发送模型提示、任务或源码。通过表示目标网络可达，不能推导成员已经登录、模型额度可用或任务必然成功。本机代理的实际连接地址与端口吻合时，额外显示“已确认经过所选本机代理”；无法观察则不显示该结论。测试时间和耗时可见，详细说明折叠，改动配置后旧结果标为需重新测试。

绕过规则支持主机名、域名后缀和 IP，不承诺 PAC、通配符、CIDR 或代理端 DNS。本机工作台、MCP bridge、审批和预览固定直连；不只依赖成员是否遵循 NO_PROXY。

## 运行时与真实边界

连接探针、登录确认、模型能力读取和执行启动共用 `NetworkSettingsService`。全局配置注入工作台自有目录请求；成员配置经同一解析器生成大小写一致的代理环境，不修改共享 `process.env`。直接连接清除已知代理覆盖。使用代理失败不会偷偷回退直连，TLS 校验保持启用。

每次执行在启动前持久化网络快照，区分 `prepared` 与 `started`。当前执行沿用启动快照；重试、追问和新的进程重新解析最新网络配置，原上下文、文件及模型设置遵循已有恢复契约。网页与 MCP 读取同一个“本次启动 / 下次启动”诊断，不以新设置补写旧任务历史。

网络变化使受影响成员的能力缓存失效，保留最后已知登录证据。成员独立设置没有实际变化时，不因无关全局修改失效。网络诊断不可读也不隐藏已有任务和审批诊断。

| 执行边界               | 记录方式    | 限制                                        |
| ---------------------- | ----------- | ------------------------------------------- |
| 工作台持有的 HTTP 传输 | enforced    | 仅限实际由此传输发出的请求                  |
| ACP 进程环境           | cooperative | 环境已传入不能证明 Agent 所有自有工具都遵循 |
| 保留原有行为           | unavailable | 不声称这次配置控制了其原有路由              |

本机 bridge 使用独立的直连 HTTP 传输，拒绝重定向，避免代理收到本机授权。LocalRunner 和工作树仍不是网络沙箱。自动文件审批、命令及越界询问、MCP 工具权限、人工审阅合并均保持原样。

## 接口与存储

第 19 次迁移 `0018_network_settings` 新增全局设置、成员例外和执行网络观察表，位于 `NetworkSettingsRepository` 接口之后。保存有版本比较和事务；删除成员清理例外，执行快照独立保留。旧任务显示当时设置未记录。

公共输入使用严格 Zod 校验，拒绝带凭据地址及未知成员。当前没有代理密码字段或秘密引用，不能把未来的凭据存储设计当作已交付能力。

- `GET /api/system/network`：已保存设置、有效摘要、真实支持能力与版本。
- `PATCH /api/system/network`：全量草稿与 `expectedRevision`，一次保存。
- `POST /api/system/network/test`：有界连接草稿，固定官方目标，结果不保存配置。
- MCP `list_agents` 与 `get_task`：读取有效摘要及同源执行诊断，不发布修改系统设置的 Worker 工具。

## 验收与后续

用户提供 `127.0.0.1:7897`，真实目标检查返回 200，观察到 TCP 对端为该地址。真实 Codex 和 Antigravity 均完成无提示初始化及能力读取，分别观察到 17、3 次 CONNECT 经受控观察中继转至该代理；只记录目标和时间，不解密 TLS，不复制凭据。这证明已观察到的初始化流量，不能替代真实模型任务的全流量验收。

确定性本机 ACP 进程验证了两个代理、能力读取、执行首轮、失败后切换代理直接重试、进程重启及追问，保留文件、上下文、启动网络快照与项目审批策略。其执行证据不冒充 Provider 模型调用。UI 验证覆盖未保存测试、成员例外、版本冲突、保存核对、返回草稿和固定操作栏。

本批没有新增模型提示或安装 Agent；新增成员按用户要求暂缓。代理认证、SOCKS 与其它适配器的专门支持留待后续按真实版本及需求扩展。具体结果见 [验证记录](../reviews/network-proxy-20261025.md)。

## 依据

- 发布运行时 Node 22.22.2，内含 Undici 6.24.1。该版本 [HTTP 文档](https://github.com/nodejs/node/blob/v22.22.2/doc/api/http.md#built-in-proxy-support) 和 [启动参数文档](https://github.com/nodejs/node/blob/v22.22.2/doc/api/cli.md#node_use_env_proxy1) 是 HTTP(S) 代理环境的版本依据，不能据新版 Undici 文档承诺 SOCKS。
- [Codex ACP](https://github.com/agentclientprotocol/codex-acp) 和 [Antigravity IDE 文档](https://antigravity.google/docs/ide/extensions) 不能单独证明所有出站流量；本机实际观察与可控边界分别记录。
