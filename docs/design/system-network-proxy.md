# 系统设置与每成员网络代理

状态：2026-10-25 设计定稿，尚未实现代理配置与运行时接线。日用版仍采用原有网络行为；已有模型设置、常用方案和目录接入不受本设计变更。本文是实现与验收依据，不将设计稿或环境变量传入视为真实代理流量证据。

## 用户操作与入口

顶部加入带文字的“系统设置”，进入“网络代理”。不放在任务输入区，不要求用户编辑 ACP 启动命令或 JSON。系统设置只展示已经实现的分类，初期只有网络代理，后续可扩展日志、存储等，不预放空菜单。

成员卡增加简短网络摘要，例如“网络：跟随全局”或“网络：单独代理”。点击直接打开系统设置并定位该成员，返回后保留项目、会话、输入草稿和原滚动位置。模型、思考等级、常用方案仍在原“运行设置”中，网络与模型偏好分开保存。

主面板先展示全局设置，再展示成员例外；普通用户只有一个地址需要填写。

```text
系统设置                                  网络代理

全局连接方式
 [保留原有设置]  [直接连接]  [使用代理]

 代理地址  [ http://127.0.0.1:7890                ]
 [测试此代理]      未测试
 ▸ 认证与不使用代理的地址

 适用于工作台联网和下方跟随全局的成员
 工作台、MCP 与预览的本机通信固定直连

成员连接方式                         搜索成员…
 Codex        [跟随全局 ▾]   http://127.0.0.1:7890
 Antigravity  [单独设置 ▾]   http://127.0.0.1:8080  [编辑]

 1 位跟随全局 · 1 位单独设置

 尚未保存的修改               [还原修改] [保存设置]
```

以上地址仅为界面示例，不自动填入实际配置，不读取或修改 Codex、IDEA 或 Windows 的全局代理。

## 两级设置与优先级

| 层级 | 选择 | 具体含义 |
| --- | --- | --- |
| 全局 | 保留原有设置（初始默认） | 保持当前服务及每位成员的原有行为，不擅自导入宿主、系统或环境中的代理 |
| 全局 | 直接连接 | 工作台自有出站请求直连；对跟随全局的成员清除已知代理环境覆盖，记录边界能力 |
| 全局 | 使用代理 | 工作台自有联网与跟随全局的成员使用这份代理配置 |
| 每成员 | 跟随全局（默认） | 使用全局规则，显示解析后的连接方式和来源 |
| 每成员 | 直接连接 | 覆盖全局代理，明确请求该成员直连 |
| 每成员 | 单独设置 | 仅此成员使用自己的地址、认证引用和绕过规则，不受全局地址调整影响 |

优先级为：成员明确选择 → 全局设置 → 保持原有行为。切换全局模式不会覆盖成员的单独设置。切换下拉框不立即丢弃已输入的地址；未启用配置明确标记为不生效，执行解析只读取当前选中模式。

“保留原有设置”与“跟随系统代理”不同。Windows 的系统代理、PAC/WPAD、浏览器代理与进程环境不是同一种机制；没有对应实现和证据前，不提供会误导用户的“已跟随系统”状态。

## 表单交互

- 一个地址输入框，允许直接粘贴带协议的地址；未带协议时，在保存前明确显示规范化后的 HTTP 地址。协议、主机、端口错误就地说明，不提交后再报笼统失败。
- HTTP、HTTPS、SOCKS5/代理端 DNS 纳入能力模型；按当前控制台运行时和成员适配器的真实支持展示。未支持的协议明确禁用并说明，不把某个库的新版本能力当作当前安装版本能力。HTTP 与 HTTPS 目标的区分放入进阶区域，默认共用一个代理。
- 认证与绕过地址默认折叠。本机通信的保留地址只读；自定义绕过规则显示实际支持的语法，不假定各语言都支持 CIDR 或相同通配符。
- 成员列表支持搜索；“单独设置”打开当前面板内的成员详情，显示成员名、来源和当前有效地址。小屏转为纵向卡片，操作按钮不挤出视口。
- 整个页面使用一份修改草稿及固定底部操作栏。全局与成员例外一次原子保存；任一输入无效都不部分保存。离开有修改的页面时提供“继续编辑 / 放弃修改”，关闭后恢复原焦点。
- 保存后显示“已保存，下次启动成员时使用”。只有真正开始新进程后，才显示该次执行已传入的设置；不会自动终止或重启运行中成员。
- 全局修改前后显示受影响成员数；已有单独配置的成员明确列为不受影响。版本冲突保留本地草稿，提供读取最新版本和差异核对，避免另一窗口的设置被静默覆盖。

## 测试、诊断与修复

“测试此代理”使用当前草稿，不需要先保存。结果带测试时间、目标、配置摘要和配置版本；改地址、认证或规则后，旧结果立即标记“配置已变化，需要重新测试”。

测试分层展示，不能以代理端口能连接就声称 Agent 已可用：

| 层次 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 格式校验 | 地址及本地支持的协议有效 | 代理程序正在运行 |
| 代理连接 | 连接、握手或认证阶段成功 | 目标服务可达、模型已授权 |
| 目标网络 | 经过所选连接方式访问指定官方测试目标成功，TLS 正常 | 模型额度、授权和任务成功 |
| 成员检查 | 使用同一份解析配置启动实际适配器完成无提示检查 | 所有 Agent 自有工具或后续请求都被强制代理 |
| 实际流量核对 | 在受控代理或可信观察点确认该次目标连接实际经过代理 | 未观察到的其它流量同样受控 |

测试不发送模型提示，不提交任务文本、源码或登录凭据到任意测试站点。目标来自有界官方目标清单；不提供任意 URL 探测器。成员检查由用户主动触发，不在保存、打开菜单或轮询时启动全部成员。

页面摘要区分“已保存”“下次启动使用”“已传入，尚未验证流量”“网络检查通过”“适配器不支持”。连接失败显示可操作原因：代理未响应、代理认证要求、目标网络超时、TLS 校验失败或不支持的协议。不能归因的超时明确写原因尚未确认，不一律变成“需要登录”。

任务失败后提供“打开此成员代理设置”和既有“重试本轮”。重试保留上下文与已有文件，采用新的网络配置；已有模型请求设置仍按原任务快照冻结。配置为使用代理时，控制台可控请求失败直接报告，不静默切换到直连。

## 真实生效范围

ACP stdio 是本机进程通信，网络代理作用于适配器及其后端请求，不作用于 stdio 本身。需要覆盖所有启动路径：后台启动登录确认、连接探针、模型能力读取、任务首轮、负责人和协作者、失败重试、恢复会话、继续追问。网页和 Codex MCP 使用同一解析服务。

当前源码有两个启动环境组装点：

- `packages/acp-runtime/src/process-control.ts` 的 `environmentFor`：连接、认证和设置读取。
- `apps/server/src/runtime-composition.ts` 执行启动段：真实任务及续轮。

`LocalRunner` 的默认继承列表不含代理变量；仅在 UI 存一份地址或改服务端环境都不足以接通这些路径。两处应改为调用同一个 `AgentNetworkResolver`；禁止逐次任务修改共享的 `process.env`，避免并行成员串用代理。

解析结果通过适配器边界应用：标准代理环境的大小写形式统一处理，清理遗留的冲突项；Node、原生程序或有明确版本契约的适配器分别实现支持。需要原生配置时使用对应适配层，不在领域层按供应商或模型名称分支。

控制台自有 HTTP 请求采用每请求或每配置版本的传输实例，避免切换全局 dispatcher 时污染其它成员。本机 bridge、状态查询、审批回调和预览使用明确的直连通道；仅给 `NO_PROXY` 添加字符串不足以证明这些关键本机请求被保护。外部受控联网与本机通信必须分开解析。

每次新执行尝试在进程启动前冻结有效网络版本，记录来源和脱敏摘要。运行中的进程沿用启动时设置，接收补充指令时也不热切网络；下一次新进程、重试或追问重新解析最新网络设置，恢复原会话与模型参数。网络快照与模型设置的冻结周期不同，不能因为原任务网络失败而让每次重试永久使用旧坏代理。

代理变化会使相关能力观察和连接测试失效，显示“网络设置已变化，待复核”，但保留最后已知登录证据。只使实际解析结果变化的成员失效，独立代理的成员不因无关全局改动而重复探针。

## 权限、认证与可观察性

- 适配器读取环境属于 cooperative。只有控制台持有并实际选择的传输路径可以标为 enforced；没有对应支持时是 unavailable。环境已传入不等于所有 Agent 自有联网都被拦截，LocalRunner 和工作树不是网络沙箱。
- 自动审批、命令询问、越界询问、MCP 工具权限、项目范围与人工审阅合并都保持独立。模型设置或普通任务提示不能修改系统代理。
- 代理认证凭据属于单独的本机秘密存储。普通 SQLite、任务上下文、审计事件、MCP 响应和导出文件只保存引用及脱敏状态；运行时在执行边界读取。Windows 使用受支持的系统保护实现，接口允许其它系统接入。凭据存储不可用时禁止假装已保存密码，也不回退明文。
- 地址中带用户名或密码时引导转入认证输入，不把整段原始 URL 当作公开设置保存。密码不放命令参数，不写浏览器持久缓存，重新打开仅显示“已保存，可更换”。清空与替换采用显式动作。
- 确认代理路径不关闭 TLS 校验、不添加忽略证书选项。代理或网络故障与成员认证失效分开呈现。
- 诊断记录有效来源、配置版本、连接方式、脱敏地址、应用方式、执行边界和观察时间。只观察必要的目标连接元数据，不捕获 Provider 认证头、请求正文或 TLS 明文。

## 接口与存储分层

新增 `NetworkSettingsRepository` 和独立迁移（接当前第 18 次迁移之后），保存全局设置、按 Agent ID 的例外及安全版本。成员删除时清理其网络例外，历史执行快照保留。未知旧任务显示“当时网络设置未记录”，不以当前配置补写历史。

公共输入使用严格 Zod 校验。建议接口：

- `GET /api/system/network`：已保存设置、成员有效摘要、支持能力与版本，无密码。
- `PATCH /api/system/network`：`expectedRevision` 与全局/成员变更，一次事务保存。
- `POST /api/system/network/test`：有界草稿与固定测试目标 ID，返回分阶段结果；不保存、不提示模型。
- 任务诊断附加 `networkObservation`，区分本轮启动值与下次采用值。

MCP 可读成员有效网络摘要与失败诊断；修改仍由明确系统设置操作完成，不作为 Worker 可调用的普通工具发布。当前 Codex 客户端自身的代理不在这套设置的管理范围内。

## 实现验收

1. 修改全局后，跟随者采用新地址，单独代理与直连成员保留各自设置；网页与 MCP 发起同一成员的启动解析一致。
2. 用两个不同的受控本机代理并行验证两个成员，记录实际到达的连接及目标；不以环境变量存在替代流量验证。
3. 真实 Codex 与 Antigravity 逐个验证连接、能力读取、实际任务和追问；有不支持或无法观察的路径明确标注，不能宣称全量代理。
4. 保存时不重启活跃任务；新尝试采用新版本，网络失败可改代理直接重试，上下文、文件、模型设置和人工合并状态保留。
5. 本机 bridge、审批、事件更新、文件差异与预览不经过外部代理。代理拒绝或停机时仍能打开工作台修复。
6. 代理故障不改写为登录失效；展示有效设置、检查阶段和可定位的修复入口。
7. 重开/迁移、两窗口版本冲突、凭据隔离与实际执行边界使用有意义的确定性测试；不为了这份设计重复现有无关边界测试。

实现前还需从已安装版本或官方版本契约确认各适配器的 HTTP(S)/SOCKS、DNS 与子进程继承行为。尚无可用代理地址，因此没有执行新的代理流量验收，也没有修改当前用户网络配置。

## 依据

- 本机发布运行时为 Node 22.22.2，内含 Undici 6.24.1。Node 该版本的 [HTTP 文档](https://github.com/nodejs/node/blob/v22.22.2/doc/api/http.md#built-in-proxy-support) 和 [启动参数文档](https://github.com/nodejs/node/blob/v22.22.2/doc/api/cli.md#node_use_env_proxy1) 说明 HTTP(S) 代理环境需要正确启用；不能据新版 Undici 文档直接承诺本机 SOCKS 支持。
- 当前 [Codex ACP 项目](https://github.com/agentclientprotocol/codex-acp) 和 [Antigravity IDE 接入文档](https://antigravity.google/docs/ide/extensions) 不足以证明本机所有出站请求遵循代理。后续按已安装版本检查和真实流量证据补齐。
