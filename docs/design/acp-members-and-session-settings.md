# ACP 成员接入与运行设置交互方案

状态：2026-10-26 已实现能力读取、真实应用、成员默认、追问继承以及网页/MCP 共用。每成员多个命名方案、能力缓存观察与目录来源关联已发布并通过网页实操。成员管理分为“已接入 / 添加成员”，新增显式一键安装、私有运行环境和安装后登录使用。更多厂商的真实任务验收仍需逐个完成，不将目录收录视为已安装或已授权。

当前实现：打开输入旁“运行设置”，按需读取 Agent 可用选项，选择后用于下次发送或保存成员默认；任务页显示本轮实际确认值。模型先应用，依赖选项以新的完整返回重新验证，失败不发送任务提示。请求值与实际值分别持久保存，配置通知在提示之间到达也会更新记录。

本机实际读取结果：Codex 适配器提供 7 个模型，默认模型有 6 档思考等级，切换模型后可选档位会变化；另有快速模式。Antigravity 当前仅提供 Gemini 3.8 Flash 和 Low/Medium/High。两者均未提供可配置的上下文长度，用量与容量仍显示 Agent 上报值，不构造滑块。具体选项以每次读取为准。

## 实施前的缺口（历史基线）

- `packages/acp-runtime/src/runtime.ts` 的 `newSession` 仅返回 `sessionId`，恢复会话也未保留返回的配置状态。`SessionRef` 没有会话配置模型，运行时没有公开设置配置的方法。
- 本机 SDK 1.5.1 已包含 `session/set_config_option`，不应先假定必须升级依赖或为每个厂商另写一套模型列表。
- 成员注册保存启动入口、认证管理方式、协作资格和权限，没有独立的运行预设。启动配置与模型偏好不应混为一体，否则改模型容易牵动连接、认证和程序身份检查。
- 当前工作台实际显示 43 个目录产品；接入步骤、产品目录和已注册成员共处一个长面板，产品卡未清楚展示本机安装/已接入状态。已有目录缓存、入口检测、批量导入和连接恢复能力可以复用。
- 模型窗口用量目前只在过程面板显示。这是 Agent 上报的观察值，不是用户已配置的上下文上限。

## 日常交互

### 添加成员

成员管理分为“已接入”和“添加成员”两个视图，避免新接入表单与旧成员长列表混排。

添加流程：选择产品并点击安装 → 自动准备运行环境和检查连接 → 登录并使用 → 按需读取可用设置。已有程序仍可显式选择本机入口。

产品行统一展示名称、说明、版本、平台与接入状态，对应一个主要动作：

| 状态           | 主要动作                         |
| -------------- | -------------------------------- |
| 已接入         | 使用 / 打开成员设置              |
| 提供本平台分发 | 安装；自动准备运行环境和检查连接 |
| 检测到本机入口 | 接入此入口；多个入口时再选择     |
| 常用位置未发现 | 查看官方安装方式或检查其它目录   |
| 自定义 ACP     | 粘贴命令或导入配置，预览后接入   |

搜索同时覆盖产品和已接入实例。同一产品可以有多个独立实例，但不因不同模型预设而重复注册程序。为准确显示状态，应保留注册来源及产品引用，不能仅靠名称字符串猜测产品身份。

默认不要求用户填写 command、args、cwd 或环境变量。安装目录、程序入口、协作权限和诊断信息放入进阶区域。目录加载不触发下载、认证或模型提示；用户点击某个固定版本的“安装”后才提交幂等安装，版本已变化时停止并要求重新核对。Node.js 使用发行包配套运行时，Python 使用校验过的私有 uv 和独立环境；不全局安装。可以显式检查当前显示产品的本机入口；这是限时文件元数据观察，不能保证扫描全机或代表已安装、能连接、已登录。导入 IDEA 配置只提取经过验证的入口信息，不复制登录凭据，也不自动授予 MCP 或工具权限。

安装、连接和登录是三个独立状态。登录方式只使用 Agent 实际声明的方式：普通方式调用 ACP authenticate；terminal 方式仅在宿主具备交互终端支持时声明能力，并以该方法的参数和环境替换普通启动设置，保留解释器入口。终端成功退出才确认登录，失败或取消保留页面并允许重试。执行中及已有登录检查期间拒绝重复登录；服务关闭时结束所属进程树。登录成功只选择未发送草稿中的成员，不发送模型提示。

来源关联记录用户选中的目录产品及版本，并绑定当时启动入口摘要；它不是软件签名或供应商身份认证。旧成员按名称或文件名匹配时只显示“可能相同”，须显式关联。改动启动入口后标记“入口已变更”，不会据此重置登录或修改权限。

### 发任务

输入区附近保留轻量运行栏：

```text
执行成员 [某成员 ▾]  运行预设 [日常开发 ▾]  [运行设置]
模型 [Agent 默认 ▾]  思考等级 [Agent 默认 ▾]  上下文 [查看]
```

未读取到实际选项前，展示“尚未读取 / 由 Agent 管理”，不显示虚构的可选模型。读取成功后使用 Agent 返回的名称和取值。模型、思考等级等常用设置就地修改，不要求用户离开任务去寻找成员配置页。

同一成员可以保存多个预设；成员卡仅保留使用、运行设置和更多操作。停用、移除、连接详情不与日常使用同等突出。负责人资格仍是独立能力，不由模型名称或预设名称决定。

### 运行中与追问

运行中显示“本轮实际设置”，编辑后的偏好标注“下轮使用”。默认在下一次提示开始前应用，避免中途悄悄切换参数。当前任务和其他成员不随默认预设变化而改变。

追问沿用此前已确认的设置；需要新建 ACP 会话时重新应用并读取确认结果。若 Agent 自动切换模型，更新实际记录，并保留用户原先请求的值。选项失效或设置被拒绝时，在发提示前解释原因；不得静默换成其他模型继续执行。

## 参数应如何呈现

| 项目               | 交互及真实性要求                                                                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| 模型               | 从当前 Agent 会话的实际可选项读取；区分用户选中与 Agent 已确认生效                                       |
| 思考等级           | 使用实际提供的等级与名称，不假设所有 Agent 都支持同一组 low/medium/high                                  |
| 模型上下文容量     | Agent 提供可调配置时显示选择器；否则只读显示已知容量或“由模型决定 / 未上报”                              |
| 已用上下文         | 显示当前执行会话上报的 used/capacity，未知不计为零，不跨成员简单相加                                     |
| 工作台带入资料预算 | 单独控制历史、记忆和文件文本的带入范围；明确它不会修改模型窗口容量。字节/字符预算不能伪装成精确 token 数 |
| 其他配置           | 按能力渐进展示；认证、自动审批、危险执行模式与模型设置分开处理                                           |

模型变化可能改变思考等级和其他选项，界面必须整体更新配置状态。多项设置部分应用失败时不发送提示，展示已确认的实际配置，不声称完成原子回滚。未知类型保留 Agent 默认，不构造可编辑但无法生效的控件。旧 Agent 的模型接口可以由兼容适配器处理；只有文档明确、版本匹配的启动参数才能作为备选，不做任意命令参数注入。

## 扩展实现边界

1. **通用协议层**：保留并验证 `configOptions`，支持读取当前配置、设置值及接收 `config_option_update`。优先使用标准能力；旧模型接口兼容放在适配器中，领域与 UI 不按厂商写分支。
2. **独立运行预设**：预设关联成员实例，保存用户偏好，不携带凭据或扩大权限。任务角色、成员连接、运行预设和 ACP 会话保持分离。
3. **执行链生效**：发送时冻结请求设置，在实际会话应用；以完整返回状态确认，记录请求值、实际值、失败及能力来源。仅改浏览器下拉框不算实现。
4. **持久与共用**：默认预设由服务端保存，网页与 Codex MCP 使用同一接口和执行逻辑；存储保持在仓储接口后。每次执行保留设置快照，旧任务没有相关记录时如实显示未知。新增持久状态须覆盖旧数据兼容与迁移。
5. **优先级**：本次显式覆盖 → 当前会话已确认设置 → 成员默认预设 → Agent 原生默认。修改默认只影响后续选择，既有会话保留自身设置。
6. **能力缓存**：绑定成员配置版本、可观察登录就绪证据、探针会话摘要与观察时间，五分钟后标记过期；模型列表不是永久的产品常量。ACP 未暴露账号身份时明确说明此限制，不将就绪证据当作已识别账号。按需读取并限制等待时间，不在页面每次刷新时启动全部 Agent。默认或方案保存必须先核对一组完整可用设置；缓存失效与探针失败不会改变原有默认。
7. **权限边界**：模型选择不修改自动审批，不自动开放 MCP，也不把 Agent 的危险模式作为普通模型参数。控制平面仍只保证经它转发操作的策略检查，不声称拦截所有 Agent 自有工具。

## 实施顺序与验收

第一批已打通真实会话配置读取、选择、执行前应用与确认，保存本轮请求与实际配置快照，并提供输入区的模型/思考选择。真实可用选项已核对，未承诺两者支持相同控制项。

成员默认、跨轮次继承和覆盖已接通同一套 MCP 参数。每成员最多 32 个可选命名方案、128 个含归档记录，支持重命名、归档和恢复；方案与成员默认分开。MCP 可以用 `sessionPresetId` 选择方案，服务端首次接收任务时复制值与方案版本，之后方案改名、修改或归档均不改变已接受任务。追问默认沿用上一轮确认值，显式方案仅影响新轮次。通用表单适用于兼容协议的成员，其他适配器仍需逐个真实验证。

目录接入复用现有入口检测、导入与恢复能力；明确分开来源关联、本机入口观察、安装、连接和登录状态。目录注册与已有成员关联须确认当前产品版本；显式点击安装才安装该固定版本，失败文件与旧版本保留。

协议与安装参考：[ACP 简介](https://agentclientprotocol.com/get-started/introduction)、[官方目录分发格式](https://github.com/agentclientprotocol/registry/blob/main/FORMAT.md)、[ACP 登录](https://agentclientprotocol.com/protocol/v1/authentication)、[JetBrains ACP 接入](https://www.jetbrains.com/help/ai-assistant/acp.html)。协议层保持供应商中立，自动安装和运行环境管理由本机适配器提供。

验收应覆盖：两个成员设置互不串用；模型变化后选项联动；设置拒绝不显示已生效；重启保留默认预设；追问保留原设置；实际执行记录与网页/MCP 一致。涉及新执行行为使用确定性测试，旧库兼容使用迁移测试，最后用真实适配器核对设置和一个实际任务。模型参数变动不改变现有审批与人工合并流程。
