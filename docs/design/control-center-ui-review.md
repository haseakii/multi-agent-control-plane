## 主要发现

### P0：日常任务被配置表单挡在后面

1366×768 下任务区始于文档 Y≈1916，审批始于 Y≈2858–2878；差异来自浏览器
字体/布局。完整 Agent 注册表单和大标题出现在日常执行信息之前。
任务缺少目标/子任务层级和“现在需要我做什么”的优先视图。

方案：压缩项目栏与标题，默认进入任务工作台；左列目标/任务，右列所选任务详情。
在首屏显示待处理审批和阻塞说明，Agent/Boss 配置进入二级区域。

### P0：状态没有映射为符合状态机的动作

现状任务卡只有状态、目标和结果按钮，没有取消/恢复入口。这里的缺失应按状态区分：

| 状态/资格 | UI 应提供 | 不应提供或暗示 |
| --- | --- | --- |
| 有效非终态执行，例如 `running`、`waiting`、`waiting_approval` | 查看记录；符合权限时取消；待审批时检查并明确决定 | 自动审批、无边界取消 |
| `failed`，最新 attempt 为 failed/interrupted、允许重试、无活动执行且依赖满足 | 查看失败记录；明确创建新尝试的恢复动作 | 取消失败终态；只凭 `task.state=failed` 保证可恢复 |
| `failed` 且最新 attempt 明确不可重试 | 失败说明、诊断记录 | 可用的恢复按钮 |
| `completed` | 结果、消息与执行记录 | 取消、恢复 |
| `cancelled` | 已保存上下文与取消记录 | 隐式恢复原任务 |

后端已有 `POST /api/tasks/:id/cancel` 和 `POST /api/tasks/:id/resume`，并非需要
发明新执行动作。`resume` 会创建新 attempt；不保证可继续原 ACP 会话。
`TaskEngine.retryAssignment` 检查最新 attempt、retryable、依赖与终态；运行时还检查
活动执行和 Agent 可用性。当前快照不含全部恢复资格，正式接入时应从服务端提供
明确 action eligibility，或在操作时展示服务端拒绝，不能让前端自行推断授权。
取消父任务会影响其子树，确认框应明确列出作用范围；原型所选的是叶子任务。

### P1：审批、消息与产物离任务上下文太远

审批位于页面下部；资源主要以原始 JSON 展示。建议在任务内解释请求方、动作、
资源和本次作用范围，保留原始详情展开。`enforcementMode` 必须沿用实际值，
不能把 cooperative/unavailable 文案升级为强制执行。

消息和产物应按所选任务关联，辅以项目级入口；让用户知道是输入、响应还是结果，
而不是仅依靠 Agent 名和产物 ID 寻找。产物采用友好名称，保留 ID 供诊断。

### P1：结果预览及错误反馈可见性不足

一次实际渲染中，点击结果后预览文档 Y≈2508，点击时视口 Y≈1683，高 768；
预览头部仍在视口底部以下，焦点留在原按钮。建议详情内预览，打开时移动焦点，
关闭后返回触发按钮。动作错误位于页面顶部，不应要求用户回滚长页面才看见。

忙碌与失败应就近呈现，保留草稿、避免重复提交。现状已经具备 busy 锁、
错误 `role=alert`、部分状态通知与表单标签，这些行为应保留，不因视觉重排退化。

### P2：内容密度与可访问性

现状长内容在已测 1024 宽视口未产生横向溢出，不能据此宣称存在溢出缺陷；
但长内容显著增加滚动距离。建议折叠次要诊断信息、按任务分组，状态同时用文字和颜色。
原型保留暗色工具风格，缩小展示性标题，减少同权重卡片；提高正文与辅助文字层级。

键盘方面保留原生控件和焦点样式；新增跳到工作区链接。原型对话框 Escape 与焦点
返回已检查，详情标签页提供键盘焦点移动。尚未完成屏幕阅读器全流程或对比度认证。

## 独立原型的范围

打开同目录 `control-center-proposal.html` 即可，不需要启动任何服务。
原型没有 fetch/XHR/WebSocket，不连接 API，不启动 ACP，不写正式数据。
顶部始终标注本地模拟；批准、拒绝、取消、恢复和新目标仅改变页面示例状态。
审批确认展示单次范围。失败示例明确假定最新 attempt 可恢复；生产资格必须由后端决定。

第一版以一个工作台总览和一个任务详情为主。Agent 配置和首次进入只展示信息层级，
不是完整页面实现；其交互不代表已有后台配置能力。状态切换器属于评审工具，不属于拟上线产品。

## 最小落地顺序

1. 先重排信息结构：项目栏、任务列表/层级、选中任务详情、待处理提醒；保持现有请求与持久化逻辑。
2. 在任务上下文接入已有审批、结果、取消和恢复；由后端返回动作资格，校准 busy/409/失败反馈和焦点。
3. 把 Agent/Boss 注册与高级运行配置移到设置区域，补首次进入引导、就绪/授权/Boss 资格区别。
4. 最后统一排版、间距、状态色与长文本策略；补 1024/1366/1440 桌面端、键盘和状态端到端回归。

本次只验证原型与现状展示，没有把方案接入正式 UI，也没有新增真实任务或付费调用。
本次评审服务结束时停止；静态原型和截图可独立演示，不影响已有服务。
