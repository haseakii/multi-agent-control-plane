# 发布、部署与外部接入收敛

状态：2026-10-25 流程审查与后续验收要求；本文不代表安装器、升级管理器或 HTTP 公共接口已经实现。

目标：一个完整安装包、固定的日常入口、一次外部接入配置。用户处理项目、任务与权限，程序管理版本、路径、备份和启动。网页与 MCP 继续共用协作引擎、任务记录、附件和审阅流程。

## 当前问题

- Windows release 已包含 Node、网页及依赖，但日用启动脚本仍直接引用 `.run/<日期>/release`，切换版本要联动修改两个 CMD、后台启动器和连接文件。
- MCP 已有固定 `scripts/collaboration-client.mjs` 入口，但仍依赖仓库目录和私有验证目录，尚未成为随正式包交付的统一安装入口。
- `connect-mcp.mjs` 首次接入需要 URL、客户端名、项目、授权文件及连接文件等参数，且创建后重复运行直接报错；缺少面向用户的连接信息生成、状态说明和受控更新流程。
- 首次使用、开发调试、日常启动及维护恢复分散在不同文档。正常使用步骤应单独呈现，维护细节按需展开。

## 目标操作流程

| 场景                | 用户操作                                   | 程序负责                                                 |
| ------------------- | ------------------------------------------ | -------------------------------------------------------- |
| 第一次运行          | 解压完整包，打开工作台，选择已有项目和成员 | 初始化私有数据、后台启动、显示明确就绪状态               |
| 日常使用            | 打开网页，或在已接入的 Agent 中直接发任务  | 复用后台实例、必要时启动、恢复记录与附件                 |
| 升级                | 选择新版并确认一次升级                     | 检查空闲状态、正常停机、一致备份、验证包、切换、健康检查 |
| 接入另一个 AI Agent | 选择允许访问的项目，复制一份标准 MCP 配置  | 生成独立客户端身份和固定入口，显示连接状态与撤销入口     |
| 接入业务系统        | 使用公开且版本化的 HTTP 接口或薄 SDK       | 共用同一应用服务、客户端授权、诊断与审计                 |

确认项目范围、敏感操作和审阅合并继续保留。简化发生在重复配置、路径和维护步骤上。

## 实施顺序

### 1. 先统一发布与启动入口

- 正式包内提供固定启动入口，支持启动、状态、停止；Windows 可继续保留中文快捷入口。外部系统引用固定位置。
- 安装目录分开保存版本、私有数据和当前版本指针。只通过一个版本选择服务改变指针；网页、后台与 MCP 都从这里解析当前版本，禁止各自替换日期路径。
- 构建与发布封装成一个维护命令，串起编译、必要验证、打包、包完整性及原生依赖探针，产出带版本和校验信息的完整包。开发工具仅属于构建端。
- 升级管理器统一编排现有停机、备份、迁移与启动能力，输出一个成功或失败结果及可用的恢复入口，不让用户逐条执行维护命令。
- 数据迁移与程序切换分别记录。程序回退须检查数据库兼容性；需要恢复时从一致备份进入新私有目录。保留原件，不强删未知锁或让旧程序直接打开新数据库。

### 2. 再收敛外部接入

- MCP 是支持 MCP 的 Agent 的默认接入方式。用户只选项目并复制一份配置，程序保存本地连接和独立授权；升级不再编辑宿主的 `config.toml`。
- 安装包直接带固定 MCP 入口；不要求调用方安装本项目依赖、寻找编译目录或理解后台内部配置。
- 普通系统走公开的版本化 HTTP 契约，最小覆盖发现、附件上传、发任务、查状态、追问和准备审阅。薄 SDK 只封装传输，不另写任务调度。内部 Fleet 会话接口继续留在内部。
- MCP 本地文件路径只在 MCP 客户端读取；HTTP 调用方上传实际字节。远端系统不能把自己的路径当作服务端可读取文件。
- 每个接入方有独立可撤销身份，明确项目和工具范围；重连复用原授权，变更范围需确认。审批与合并不由外部客户端代批。
- 默认复用同一个本地后台。异机和远程部署作为后续独立范围处理，不因新增接入方就扩大监听地址或暴露本机服务。

### 3. 最后补首次使用与说明

- 首次只呈现运行工作台、选择项目/成员、发送任务；成员安装与登录按实际缺项引导，沿用 Agent 自管认证。
- 日常页呈现连接状态，不把状态查询变成反复登录或发模型提示。
- 发布说明只突出变化、升级入口和已知限制；开发与故障恢复文档单独保留。

## 验收标准

1. 正式包运行无需 IDEA、pnpm 或系统 Node；首次流程不暴露 `.run`、数据库路径和内部端口配置。
2. 升级只有一个操作入口，不要求手改多个脚本、数据库或宿主 MCP 配置；失败能说明停在哪一步及如何恢复。
3. 第二个支持 MCP 的系统只需一次标准配置，复用现有后台；首次授权后无需每次重新注册。
4. 网页与外部系统看到同一任务 ID、附件、过程、诊断与审阅状态；追问保留上下文和已有改动。
5. 原有文件自动审批、敏感操作确认、人工审阅合并和独立客户端授权都不因流程简化而扩大。

下一步交付先覆盖第 1 阶段的统一入口与版本选择，再做一份接入配置的生成与复用；不同时铺开多套安装器、部署栈或配置页面。
