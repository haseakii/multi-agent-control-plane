# V0 Delivery Plan

## Phase 0 — Repository/bootstrap
- monorepo package setup
- lint/typecheck/test baseline
- Fastify health endpoint
- SQLite migration harness
- shared identifiers/schemas

Exit: `pnpm install`, `pnpm typecheck`, `pnpm test`, and `pnpm build` succeed; CI runs on pull requests.

## Phase 1 — ACP runtime and registry
- AgentDefinition persistence
- LocalRunner
- stdio ACP lifecycle
- best-effort probe/readiness/auth-state flow
- normalized event stream
- explicit Runner-process vs ACP-session boundary

Exit: two different ACP agents can be registered and manually prompted through the server, with unknown auth state represented honestly.

## Phase 2 — Durable task execution
- Task state machine
- Assignment + execution attempts
- conversation/session references
- restart recovery
- basic Context Builder

Exit: a task can survive server restart and continue with a new or resumed ACP session.

## Phase 3 — Fleet control bridge
- capability discovery
- Fleet MCP server
- Boss selection and explicit bridge scopes
- session-level MCP attachment on supported ACP session creation/resume
- create/delegate/wait/cancel tools
- CLI/structured fallback only for supported adapters

Exit: one selected Boss can discover and delegate to a worker without hard-coded vendor logic; bridge calls are scope-checked and audited.

## Phase 4 — Messaging and artifacts
- SQLite outbox/inbox
- request/response/handoff envelopes
- content-addressed artifact store
- agent-to-agent routed messaging
- idempotent, ordered mailbox delivery and restart recovery

Exit: a Worker A with messaging scope can ask Worker B for help through the control plane; Worker B does not receive Boss privileges to reply, and the result survives restart-safe delivery.

## Phase 5 — Policy/workspaces
- allow/ask/deny policy for mediated operations
- enforcement-mode reporting (enforced/cooperative/unavailable)
- durable approvals
- LocalDirectory workspace
- Git worktree provider
- policy-controlled control-plane merge/push actions
- ACP permission-request integration
- explicit LocalRunner warning and refusal when strict enforcement is required but unavailable

Exit: dangerous mediated operations pause for approval; documentation/UI never claims that opaque local agent tools are intercepted by policy.

## Phase 6 — Web control center
- Agent registry/auth readiness
- Boss configuration
- task graph/list
- timeline/event stream
- approvals
- artifacts/execution attempts
- visible bridge scopes and policy enforcement mode

## V0 release gate
Run the full acceptance scenario in `docs/architecture/v0-scope.md` with at least two independent ACP agents and no vendor-specific role mapping.
