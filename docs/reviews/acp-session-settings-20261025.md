## 已交付

- 真实读取 ACP `configOptions`，支持模型、思考等级和公开模型参数；兼容可确认的旧模型接口。模式、自动审批和协作权限不混入模型参数。

- 重试保留已冻结请求；追问继承上一轮实际确认值，显式覆盖只影响新轮次。
- SQLite 独立仓储与第 16 次迁移 `0015_agent_session_settings`；旧任务明确显示未记录配置。
- 网页与 MCP 使用同一服务及持久记录。MCP 的 `submit_task`、`continue_task` 支持 `sessionSettings`，`list_agents` 支持按项目读取真实能力。

## 本轮发现并修复

1. 会话建立时无效配置原先可能只让执行失败、设置仍等待确认；现统一记录设置失败。
2. 提示结束后的合法配置通知原先不能落库；现使用事件接收器持久更新，重启测试确认保留。
3. 首轮设置卡和追问输入框使用同一 React key，轮询留下重复节点；已分开命名空间。真实页面连续轮询仅一张设置卡，输入草稿保持完整。
4. 运行中选下轮配置可能阻挡补充消息；运行与清理时冻结设置，补充沿用本轮，下一轮覆盖保留。
5. Antigravity 新建文件尚未识别，长正文导致审批截断。已以受控 `session/load` 读取实际 `kind:edit`、diff 元数据 `{kind:add}`；严格绑定适配器版本、路径与完整正文，扫描后使用字节数和 SHA256 审计。支持实际出现的 `Overwrite:false` 与可选说明。未知格式继续询问。

此前不支持格式的三条请求保留原记录：两轮由维护者停止，一轮审批过期后只生成未落盘说明。没有代批、追溯放行，也没有把这些轮次当作成功建页证据。旧猜测的 `{kind:create}` 未保留为支持格式。
