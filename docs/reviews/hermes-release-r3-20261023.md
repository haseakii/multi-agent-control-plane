# Hermes R3：统一标准 release 的源码接入

用户已明确选择“统一标准 release（推荐）”。本批落实该决定，不再等待数据布局选择。仅修改源码、编写回归用例和静态自审；未执行测试、类型检查、构建、打包、服务操作、模型调用、数据交接或发布。当前页面仍可能运行旧版本。本批尚待独立静审，不沿用 R2 签收。

## 正式使用与交付路径

正式包继续使用既有 `start.cmd` → `release-main.js`。默认打开 3000 端口，前台 Ctrl+C 停止；`--config` 继续相对配置文件解析 dataDir。Hermes 页面使用标准服务、同一 runtime 和 `data/control-plane.sqlite`；数据锁、完整 HTTP 关闭、日志、产物、工作区以及 backup/restore 继续沿用原链。没有新增配置页面、第二个数据库布局、第二套调度器或备份格式。

原发行器增加维护参数 `--workbench hermes --web-dist PRIVATE_WEB_DIRECTORY`，将 Hermes Web 放在包内原 `apps/web/dist`，不改标准目录结构；无该参数保留经典界面。Hermes 构建增加 `--output NEW_WEB_DIRECTORY`，要求新目录且不更新开发实例的 Web/来源标识；发行器拒绝直接使用当前开发 web-dist。构建复用现有前端许可证收集插件，生成全部实际打包依赖的许可和文件哈希。新 `workbench.json` 由 Zod 严格验证，只接受真实日常模式和构建时间；标准服务据此提供原界面需要的 `/api/workbench`。发行器同时检查固定上游提交、构建时间相符、上游 LICENSE，记录相关哈希。打包参数不是普通用户配置，也不代表已获得商业或分发许可。

以下只是维护阶段的未来构建说明，本轮未运行：

1. 从冻结源码准备标准引擎构建，以及 `node integrations/hermes-workbench/build.mjs --output NEW_WEB_DIRECTORY` 的真实 Web 构建；保留固定上游与已有锁文件，不安装新依赖，不更新旧服务 Web 目录。
2. 用原发行器 `node scripts/build-windows-release.mjs --output NEW_DIRECTORY --workbench hermes --web-dist NEW_WEB_DIRECTORY` 生成全新私有本机评估目录；原发行器仍要求已有且签名有效的指定 Node 版本和 LICENSE，并执行其原生探针。
3. 在新目录用 `start.cmd` 进入工作台；通过现有连接抽屉确认本机成员，输入任务、发送、协作、补充与继续追问。日常标准 runtime 不加载历史三轮验收预算，也不自动重置任何旧账本。

正式包不复制开发 `.run` 数据、私有 Agent 种子、登录 profile 或凭据。新空库没有预置成员；成员仍通过已有连接入口登记、检查和登录。恢复的定义保留，但路径与登录环境须重新核对；不按供应商或名称注入认证，也不启动后自动探测或登录。

## 旧数据的受控交接

维护命令新增 `backup-legacy-hermes --legacy-run OLD_RUN --output NEW_BACKUP`。OLD_RUN 直接包含 `server.json` 和 `data/state.sqlite`，输出必须在该目录之外。源码路径为：

1. 校验输入、目录/文件无链接、旧元数据和记录的 PID。存活或无法确认退出时拒绝，未取得旧进程记录也拒绝；不发终止信号。
2. 通过同一 `acquireInstanceLock` 取得旧 data 锁，再次核对进程、目录标记与混合库名。已有锁不删除、不抢占。
3. 复用标准备份函数内部核心：只复制旧 SQLite/WAL 到私有临时副本，从副本生成一致快照；检查原迁移哈希、完整性和引用产物。源库不重命名，不应用迁移，不复制登录或账本。
4. 输出仍为 version 1 `control-plane-private-backup`，由原 `verifyPrivateBackup` 校验后激活。不引入特殊恢复器。
5. 原 `restore` 在新目录生成 `data/control-plane.sqlite`、标准 config 和恢复说明。旧目录保留；失败输出保留不可运行标记；恢复不自动执行任务。新标准库还可由原 `backup` 命令再次备份。

**停机边界：** 新实例互斥由数据锁强制执行；历史无锁启动器不受该锁控制。维护人员必须停止所有旧入口及成员进程并保持停机。记录 PID 检查不构成 OS 隔离，不能拦截旧无锁程序再次启动；返回值明确记录 `stopEnforcement=cooperative-legacy-launcher`。没有自动扫描/终止其他服务或复制私有 profile。

工作区文件、外部 ACP 程序、日志和登录 profile 本来就在标准备份范围之外。数据库中的任务、成员及工作区路径保留，可能仍引用旧位置；因此原目录不能随交接删除，实际执行前核对路径和成员连接。原标准升级/恢复的版本与迁移兼容限制继续有效，不支持旧程序打开新库。
