# Hermes 真实工作台使用验收（2026-10-23）

用户明确要求使用真实 Codex 和 Antigravity，从工作台验证发送、协作、继续追问，以及过程和记录展示。本轮真实任务均由 Edge 中的工作台输入框发送，没有调用旧模拟 Agent。

## 实际结果

验收会话：[真实 Codex × Antigravity 协作与追问验收](http://127.0.0.1:8057/?task=task-4fb45c7d-87c4-4325-8d1a-304d55ffddbb)。

- 第1轮：Codex 草拟「输入任务、查看协作、继续追问」三步说明，发现并委派 Antigravity 审阅；Worker 返回两条建议，Codex 读取真实产物后汇总。
- 第2轮：在原会话追问执行中补充与完成后追问的区别；Codex 明确引用上一轮说明及建议，再委派 Antigravity，读取其产物形成区别表格。
- 第3轮：重开修正版后直接输入一句话追问，Codex 结合前两轮结果返回具体示例。
- 3 个负责人轮次、2 个子任务，共 5 个任务全部 completed。两次协作均有发现/委派、消息交接、负责人读取对应 Worker 产物的审计证据。
- 修复后的真实过程保存了 26 条公开消息快照、24 条工具状态更新及 4 份完整公开回复日志（SHA 校验通过）。相同回复快照在界面合并显示，不逐片堆叠。
- 首轮旧实现没有保存中途文字，未伪造回填；首轮最终结果和协作记录保留，实时文字及完整回复日志从第2轮修复版开始实际验证。
- 服务正常停止/重开、浏览器刷新后仍能查看三轮对话、工具记录、两位 Worker 的结果，以及继续输入框。没有引入每日3轮限制。

首轮 Antigravity 请求目录探查和写入其个人产物目录，因权限信息不完整/截短而不能批准，本次说明任务也不需要这些操作；在工作台逐项拒绝后，Agent 直接回复并完成审阅。第2轮明确要求纯文字审阅，直接完成。没有放松原权限审批门槛、自动批准危险操作或声称拦截 Agent 所有内部工具。

## 直接修复的问题

1. 原引擎只收集最终文本，中途计划/回复及 ACP 工具状态未进入工作台。现在记录 Agent 公开消息预览、工具名称/状态，聊天区与子 Agent 面板可见；每轮完整公开回复作为 log 产物保存。没有采集私有思考链或原始工具参数/结果。
2. 日志收尾被纳入执行 completion：取消时先关闭 ACP、等迭代器收尾再保存日志，关停不越过日志写入而关闭 SQLite；旧 attempt 被替换后不能提交日志。
3. 工具更新不再抹去已有名称；同毫秒事件重放不使完成记录退回 streaming，也不丢完整回复链接。
4. 工具使用 Hermes 原生 ToolChain 卡片，中文操作名和实际状态；不会将正常成功步骤渲染成系统警告。
5. 结果消息使用产物创建时间，重命名会话不会把旧结果移动到新时间。

沿用已有 events/artifacts/links 持久化接口，没有新增数据库列或表；新旧记录可同时读取。完整大文本仍走产物，快照为有限预览。进程/工作目录仍不构成OS安全沙箱。
