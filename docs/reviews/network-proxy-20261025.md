# 全局与每成员网络代理验收

2026-10-25，按用户要求优先交付网络代理，暂缓新增 ACP。首批上线到原日用地址 `http://127.0.0.1:8057/`，发布目录为 `.run/network-proxy-20261025/release-final`。首批没有安装软件、发送新模型提示或修改自动审批与人工审阅合并流程；后续真实任务验收单独记录在文末。

## 可用操作

顶部“系统设置 → 网络代理”提供全局“保留原有设置 / 直接连接 / 使用代理”；每个成员可跟随、直连或独立代理。地址补全 HTTP 协议并在保存前显示，支持无认证 HTTP/HTTPS。绕过规则折叠，成员可搜索，保存操作栏固定可见。成员抽屉和任务诊断可直接定位同一面板，返回后保留任务、草稿和原成员抽屉。

测试使用未保存草稿，不需要先改日常配置。结果区分目标可达与实际观察到代理连接。版本冲突保留草稿并展示差异，用户明确选择读取最新或重新保存；回执丢失提供核对入口。保存不重启运行中成员，后续新进程采用新值。

## 代码与数据边界

- 公共输入经严格 Zod 校验，拒绝代理凭据、路径、查询和未知成员。接口与 SQLite 仓储分离，第 19 次迁移新增设置和执行观察，不改写旧任务历史。
- 连接、登录确认、能力读取、首轮、重试与追问共用网络解析。执行启动快照不可替换；新尝试可采用新代理，原上下文和文件保留。网络变化只使相关能力观察失效，不改写成员登录状态。
- 工作台持有的 HTTP 传输标为 enforced，成员环境标为 cooperative；不把环境变量传入当作所有 Agent 流量已受控。代理失败不回退直连，TLS 校验保留。
- MCP bridge 使用明确直连传输并拒绝重定向，不仅依赖 NO_PROXY。网络设置未发布为 Worker 可修改的普通工具，模型提示不能改变系统代理。

## 交付限制

当前只支持无认证 HTTP/HTTPS 代理。SOCKS、PAC、代理凭据存储及其它厂商的专门接线尚未交付。成员遵循代理环境的能力仍由其实现决定；工作树不是网络安全沙箱。新增成员按用户明确选择暂缓，未重复索要安装许可。操作与实现说明见 [设计文档](../design/system-network-proxy.md)。
