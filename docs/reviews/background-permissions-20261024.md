# 后台启动与项目 Agent 权限验收

2026-10-24，日用版 `.run/background-20261024/release-save-fix`，地址 `http://127.0.0.1:8057/`。

## 交付行为

- Codex 已有 `local_collaboration` 连接在工具调用前检查服务；未启动时自动启动，服务异常退出后后续调用可再次启动。不重放结果不明的任务提交。
- Windows 改用本机 WMI 创建隐藏宿主，宿主将输出追加到日志，并启动引擎。没有安装服务、计划任务或外部软件；不要求用户保留终端窗口。依据 [Windows Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 中关于 `Win32_Process.Create` 的说明，另做真实退出验证。
- 仍使用原标准 release 数据目录 `restored-daily-r7/data`。Windows 原生进程句柄确认退出后，才通过文件句柄核对卷、文件 ID、UUID 并移除对应锁。进程活跃、PID 被复用、权限不明、锁缺字段或原语不可用时保留原锁。不会删除替换文件、强杀占用服务或另建空库冒充恢复成功。
- 私有本机生命周期通道提供正常停机；根目录 `停止工作台.cmd` 会等待停止及释放锁。`启动工作台.cmd` 可打开/复用后台页面，启动窗口可关闭。
- 配置中的 `startupAgents` 仅确认操作员指定成员已有登录，准备完成后才开放 HTTP 服务；不发送模型提示，不复制提供商凭据。

## 项目权限

对话顶部及选择已有项目的新任务处提供“权限”入口，无新增配置页面。设置与任务共用现有项目策略 JSON，旧记录默认每次确认；有缺省兼容和重新打开数据库验证。

- 独立工作区文件：每次确认 / 自动批准 / 拒绝。
- 命令、工作区外文件：每次确认 / 拒绝。
- 合并：审阅后确认 / 禁止；推送默认禁止，可改为审阅后确认。
- 自动文件决策必须来自适配器解析的完整文件语义；不凭 Agent 自报 action 自动放行。检查目标位于任务工作区、无路径跳转、无符号链接/目录联接、非敏感路径。
- 每项自动决定保留 ACP 请求绑定、审批记录、策略版本和事件；仍只回传 `allow_once`。待确认旧请求不会因改设置而自动批准。合并流程独立保留。
- 边界是 cooperative：不保证 Agent 自有工具被拦截，不是 OS 沙箱。当前原生自动文件编辑覆盖已识别的 Antigravity ACP 1.4.1 描述；其他适配器和未知描述保持人工确认。Codex 自有工具仍由其自身权限系统控制。
- 日用项目默认仍为每次确认；没有为现有项目擅自打开自动审批。
