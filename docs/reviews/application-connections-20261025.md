# 应用接入与 ACP 隔离安装验收

本轮把外部应用接入和 ACP 安装放进工作台已有流程。作者自查，未声称独立审阅。

## 交付

- 顶部“接入应用”按所选项目生成独立授权、完整配置和固定启动入口。Codex 输出 TOML，并可通过已安装的原生 CLI 注册；Cursor、VS Code 提供官方安装链接；IDEA 与通用客户端复制完整 JSON。不改已有 local_collaboration。
- 每个客户端只获得所选项目和所选工具集。受控网关即时校验撤销，现有任务和附件保留。任务权限仍由既有项目策略判断，没有审批、合并、推送管理工具。
- 旧 client-access 文件继续有效，数据库记录可覆盖撤销旧项。新凭据仅写入 installation/connections，数据库存哈希；导出配置不含 token。连接状态来自实际 gateway 调用记录。
- 官方产品目录提供 Windows ZIP、精确版本 npm 包的隔离安装，自动注册普通协作者、检查 ACP 初始化，再使用成员自己的登录入口。不自动赋予 Boss，不复制提供商凭据，不发模型提示。
- 安装步骤持久化；中断后标为未完成，可重试。连接失败复用已有入口。npm 使用 Node 自带的 10.9.7，禁用脚本和全局安装，独立缓存，沿用全局网络设置。目录没有校验和时界面明确说明 HTTPS 来源验证，未宣称哈希校验成功。
- 新增迁移 0020（第 21 次），保存外部接入与安装状态。升级入口保留现有后台与数据；后续升级会检查安装是否仍在进行。

## 验证

- 全量 814 项测试通过；服务端与工作台类型检查、完整工作台构建、发布包校验通过。
- 新测试验证受限项目访问、只读工具拒绝、独立撤销、实际调用时间、幂等创建、重开数据库，以及 20 → 21 次迁移保留旧记录和附件 BLOB。
- 本机真实 Codex CLI 使用隔离 HOME 安装并核对生成项，原有 MCP 与 `[windows]` 换行保留。没有写宿主 Codex 配置。
- 真实 Windows ZIP 解压使用无执行逻辑的本机测试包；错误哈希不能解压。npm 安装参数、脚本禁用、代理环境和入口选择由确定性测试验证。发布包自带 npm 已实际执行版本检查。
- 生成的完整配置经真实 stdio 子进程、固定 bootstrap 和发布包连接隔离后台，网页接口可读实际调用记录，撤销后同一进程被拒绝。
- 日用服务通过统一入口升级到 672eb0f3ab49；70 个任务、71 次执行、112 条审批、5 份附件真实字节、项目策略、代理和宿主配置均核对保留。
- 网页核对项目自动选择、应用切换、已有接入、官方 43 项目录和 Antigravity 1.4.3 安装方案。现有两成员仍已登录；未点击实际第三方成员安装或宿主客户端安装。

证据在 `.run/application-connections-20261025`（本机私有、未纳入 Git），包含测试报告、发布清单、升级记录、stdio 结果及两个界面截图。

## 实际边界

本机 stdio 配置不能直接用于远程机器。Cursor/VS Code 安装链接已按官方格式生成与校验，未冒充已完成这两个客户端的实际安装；IDEA 使用官方 JSON 添加流程。新第三方产品的实际安装、提供商登录和模型执行仍取决于用户所选产品，未将确定性测试写成提供商实机验收。uvx、非本平台包、未固定版本包或需要额外分发环境的目录项保留已有本机入口方式。

撤销作用于协作网关，不撤回已经启动的任务，不隔离同一 Windows 用户的其他进程。LocalRunner 和工作树不是操作系统安全沙箱，成员原生工具继续沿用现有边界说明。

官方接入依据：[Codex MCP](https://developers.openai.com/codex/mcp)、[Cursor 安装链接](https://cursor.com/docs/mcp/install-links)、[VS Code 安装链接](https://code.visualstudio.com/api/extension-guides/ai/mcp)、[IDEA MCP](https://www.jetbrains.com/help/ai-assistant/mcp.html)、[ACP 官方目录](https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json)。
