# 多项目接入与 ACP 成员复用验收

本轮按既有产品方向收敛日常流程。作者自查，未声称独立审阅；没有调用真实模型或新增第三方软件。

## 修复与交互

- 已安装程序持久化入口清单。重试连接优先使用清单或原成员入口，不依赖目录缓存。首次下载仍校验用户确认的目录版本。连接失败保留已安装文件，展示现有安全诊断。
- 有效接入单独按 64 条计数，撤销立即释放名额，历史折叠保留。旧文件授权与数据库覆盖项均参与相同计数与撤销判断。
- stdio MCP 的 tools/list 从已认证网关读取实时工具范围，只读客户端显示 5 个查看工具。写操作调用仍由网关拒绝；已缓存的旧工具列表不会改变权限。
- 一个接入可选择多个项目，已有接入提供“管理项目”。保存使用授权版本检查与幂等键，修改项目不改 token、连接文件、MCP 名称或宿主配置。旧 local_collaboration 接入可用相同流程更新项目。
- 成员卡和安装记录提供“使用现有程序创建成员”。每位成员有独立 ID，可分别设置模型、代理；普通协作者不会继承来源成员的负责人权限。程序入口复用，账号由 ACP 自己管理，不复制凭据，也不宣称提供商账号隔离。
- 新成员创建后刷新网络状态，避免新卡片短暂显示“代理待核对”。
- 迁移 0021（第 22 次）补齐旧授权版本并建立成员来源记录。既有安装记录兼容读取，旧入口可在重试时恢复为本机清单。

## 保留边界

原自动审批、命令确认和人工审阅合并保持不变。新成员账号是否独立取决于 ACP 自身配置和登录方式；本轮不隔离或复制提供商凭据。已有旧 stdio 进程需要重连一次以加载新的工具展示实现，后续项目授权变更无需改配置或重新安装；工具权限变更可刷新工具列表。未扩大本机后台监听范围。
