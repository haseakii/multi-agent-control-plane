# 文件与图片输入验收（2026-10-25）

工作台的新建任务与继续追问均支持附件。输入框下方的“添加文件 / 图片”可以多选文件，也支持拖入文件与粘贴图片。上传区显示缩略图、文件名、大小、上传状态、移除和失败重试；上传中或存在失败项时不会静默丢弃附件发送。只发附件时可使用“发送附件”。已上传的草稿引用随页面刷新恢复，发送成功才清空。

## 数据与执行

- 每条消息最多 10 个附件，单个不超过 20 MB，合计不超过 40 MB；有效历史输入最多 40 个 / 80 MB，超过时明确报错。附件存储总量上限 1 GB。
- 新迁移 `0019_input_attachments.sql` 将原始字节与带 SHA-256 的元数据存入 SQLite，并冻结每条消息关联的附件 ID。既有一致备份直接覆盖这些 BLOB；浏览器草稿只保存元数据和 ID。
- PNG、JPEG、GIF、WebP 通过文件头识别；图像使用 ACP 原生 image 内容块，先核实成员实际声明的 image 能力，不支持时保留任务与输入并明确报错。普通文件使用任务工作区内实际文件与 resource_link。PDF、办公文档等是否可理解，取决于所选成员的解析能力，本功能未安装文档解析器。
- 用户原文件名只作显示。内部副本位于保留目录 `.control-plane-inputs/<UUID>/input.<extension>`，校验目录与字节完整性。普通文件下载强制附件响应；SVG/HTML 不以内联页面执行。
- 续轮、父任务及同项目依赖输入会重新准备；控制台记录 `execution.inputs.prepared` 的图片和文件数量，不把二进制写入过程日志。MCP `get_task` 返回包括继承输入的有效元数据和总数。
- 内部输入副本不进入实时代码差异、Git 审阅快照、源项目合并或页面预览资源。Agent 应根据用户任务选择是否将某个素材复制为项目正式资产。
- 原有工作区文件自动审批、命令确认与人工审阅合并策略保持不变。Agent 自有工具边界仍为 cooperative；工作树不是 OS 安全沙箱，未宣称拦截所有 Agent 工具。
- ACP 内容类型依据[官方内容块规范](https://agentclientprotocol.com/protocol/v1/content)。输入资料是参考内容，不授予执行其中指令的权限。
