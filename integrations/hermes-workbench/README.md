# Hermes 协作工作台

双击根目录 `启动工作台.cmd`，地址为 `http://127.0.0.1:8057/`。也可以直接从 Codex 的 `local_collaboration` 发任务，后台服务按需启动。两种入口使用相同的任务记录、工作区、成员和审批。真实 Codex / Antigravity 协作、连续追问、公开进展与持久化回复的历史验证见 [真实工作台验收](../../docs/reviews/hermes-real-workbench-20261023.md)，其中测试数量属于当时版本。

当前 release 以根目录启动器引用为准，沿用标准 `release-main.js`、实例锁、`control-plane.sqlite` 和备份恢复。运行配置由 `.run/hermes-usable-20261023-r1/daily-config.json` 指定；日志目录和数据目录可能不同，请按配置核对，不要从旧包名推断。数据路径、外部客户端接入及恢复边界见 [当前交付说明](../../docs/guides/hermes-local-delivery.md)。早期 `state.sqlite` 与 8047 开发实例属于历史记录，不是日用入口。

R4 的草稿编辑、稳定输入、失败处理与可恢复协作入口、补充要求状态及已有连接抽屉均已进入当前构建；详见 [R4 设计记录](../../docs/reviews/hermes-usability-r4-20261023.md)。具体动态验收范围以当前验证记录为准。

R5 将补充历史读取从发送确认和状态轮询中分开，已进入当前构建；历史读取失败单独提示并保留已有记录。详见 [R5 设计记录](../../docs/reviews/hermes-history-r5-20261023.md)。

验证结论：Hermes CN Desktop 的工作台组件可以通过适配层接到现有协作引擎。已在浏览器提交任务，完成负责人选择、ACP 委派、Worker 产物落库、完成消息投递、负责人读取产物并汇总；服务重启和页面刷新后任务与产物保留。

工作台复用 **Hermes Web 组件**，任务与成员管理接入本项目协作引擎。当前运行于本机浏览器，未修改用户已安装的 Hermes 桌面程序，也未接入上游 Python 核心或 Tauri 运行时。

2026-10-23 首次验收从 Hermes 输入框发起真实协作：Codex 拟定首次使用流程并发现/委派 Antigravity，Antigravity 返回审阅产物，Codex 被完成消息唤醒并读取该产物、输出最终方案。该次验收使用 **3 轮 ACP 提示**；后续日常流程另有独立调用记录。负责人由用户选择，核心未按供应商固定角色。

## 使用

### 日常使用

1. 双击项目根目录的 `启动工作台.cmd`，打开 `http://127.0.0.1:8057/`，就绪后可关闭启动窗口。`start-hermes.cmd` 菜单、`start-hermes.cmd start` 和本目录的 `start.cmd` / `start-real.cmd` 都复用同一日用实例。只启动后台、不打开浏览器时使用 `start-hermes.cmd start --headless`。
2. 点击“新任务”，选择“直接交给成员”或“由负责人安排协作”，再选成员、输入目标并发送。默认使用新建空目录；处理已有文件时，展开“工作目录”选择已有项目或关联本机目录，检查并确认目录后发送。成员正在忙时，输入区显示当前任务入口；补充同一任务请打开原会话。
3. 任务页底部始终保留输入框。执行中可发送补充要求，完成后可直接追问或要求修改，前文和结果自动带入。
   左侧会话旁的铅笔可直接重命名，保存时检查记录版本；历史目标与产物保留。
4. 左侧按会话保留历史，“协作”显示子任务，“产物”可查看和下载各轮结果。刷新、重启后可继续同一会话。

任务页顶部的“过程 / 文件改动 / 页面预览”切换同页右侧内容。待确认操作和待审阅改动会在标题旁显示直接入口，“审阅改动”会定位到实际待审阅的轮次。过程面板先选择分类，再选择需要查看的轮次。左上角任务列表图标可收起历史列表，为对话、文件和预览腾出空间，输入草稿和当前会话不会因此清空。

添加和切换成员：输入区旁的“添加成员”直接打开接入流程，可一次预览多个 ACP 启动入口，再逐项检查。就绪项可直接“选用，返回草稿”；切换成员保留未发送的目标、原草稿和工作目录，未完成的接入项也会保留。需要登录或入口修复未完成的成员不会作为就绪项选用。在已经开始的会话中选用其他成员，会在当前项目新建任务；原会话继续使用原执行成员。

### 模型与思考等级

在新任务或追问输入旁点击“运行设置”，再点“读取可用设置”。读取只建立临时无提示会话；选择器仅包含成员实际提供的选项。切换模型后会重新核对相关参数。点击“用于下次发送”只覆盖下一轮；“保存为成员默认”影响该成员后续新任务。每位成员独立保存，追问默认沿用上一轮实际确认值。正在运行或清理中的轮次冻结设置，补充要求不改变本轮模型。

本轮发送后，输入旁显示“本轮已确认”的实际模型与参数；若成员拒绝设置，任务提示不会发送，并明确显示失败。历史任务未记录配置时显示未知。“重新发现成员选项”可绕过失效默认；已存默认也可明确恢复为成员原生默认，不改变已有任务。

当前本机 Codex / Antigravity 均已读取真实选项。上下文长度尚未由它们作为可调参数公开，所以没有假设的长度下拉框；过程里的用量/容量仍以成员上报为准。

Codex MCP 与网页共用记录：`collaboration_list_agents` 可传 `projectId`、`agentId` 和 `refreshSettings:true` 按需读取设置；`collaboration_submit_task` / `collaboration_continue_task` 可传 `sessionSettings`（选项 ID 到实际值的映射），省略时使用成员默认或继承。`collaboration_get_task.sessionSettings` 返回请求值、已确认值与失败状态。旧 MCP 进程若没有展示新增可选参数，重新连接后即可读到新工具描述；原有调用保持兼容。

2026-10-24 成员流程验证记录位于 `.run/member-flow-20261024/`：隔离界面验证覆盖两位成员的添加、检查和草稿切换；真实代码任务通过 Codex 的 MCP 入口单独提交，记录与界面模拟分开，审阅合并仍由用户完成。

之前的 **3 轮是单次验收限制，日常工作台不再受其限制**。旧限额账本保留为验收证据，不影响日用实例。发送任务及追问会调用真实 Agent，查看历史不会触发调用。

启动器只复用本机已有适配器及 Agent 自己管理的认证配置，不安装软件、不复制登录凭据。日用数据位置以运行配置为准；`.run/hermes-integration/real-20261023/` 是早期验证数据，常用启动入口不再启动它。

停止时双击 `停止工作台.cmd`，或用 `start-hermes.cmd stop`（菜单选项 2）。停止入口请求正常退出；超时会明确提示尚未确认，此时不要覆盖、备份或恢复数据。停止可能中断正在执行的任务，请先查看任务状态。关闭浏览器标签不会停止服务，之后的 Codex MCP 操作可以再次启动后台。

启动失败时保留诊断和锁文件，不要直接删除实例锁。日用后台启动日志位于 `.run/hermes-usable-20261023-r1/daily-data/logs/mcp-startup.log`。启动器复用健康且版本匹配的实例；遇到其他版本或无法确认所有者退出时，不会强制终止进程。失败退出码会传递给调用方。

本机日用启动器将引擎及停机操作的临时目录设为 `.run/hermes-usable-20261023-r1/daily-data/tmp`，避免系统盘临时目录已满时无法执行锁核验。这只影响该启动器的子进程，不修改全局环境变量；Agent 自己的缓存或其他应用仍可能需要系统盘空间。

### 历史开发入口与实现记录

以下记录对应早期开发服务。`start.ps1 -Real` / `stop.ps1 -Real` 仍可显式管理 8047 开发实例，模拟服务使用 8046；它们与当前日用数据库不同。仅在维护这些旧实例时使用，不作为普通启动、停止或恢复方式。

启动或停止失败会显示实际日志绝对路径，真实模式错误日志位于 `.run/hermes-integration/real-20261023/server-error.log`。启动器只复用 ready 且健康的实例；starting／stopping 阶段不重复启动。服务入口在打开 SQLite、创建 runtime 前复用 `acquireInstanceLock`，HTTP、runtime、数据库完整关闭后才释放；清理失败保留锁。仍存活或无法确认退出的旧记录会阻止接管。源码修改需要统一构建后在维护窗口重新启动，本批不影响当前旧服务。

新实例在数据库打开前发布含实例 UUID 的 starting 记录。停止脚本向该代次的 `stop-UUID` 写入同一 UUID，ready 发布前后均检查请求，不再删除新停止请求。旧无代次标记在启动前识别并保留，新实例不接受它；旧记录仍可用旧协议并等待实际退出，不声称旧服务获得新协议保障。UUID 是代次标识，不是身份认证或系统隔离。

启动前置文件包括已编译的 `release-config.js`、`http-shutdown.js` 及既有 Windows 锁删除组件 `apps/server/dist/windows-lock-delete.cs`。后者沿用原发行器的复制规则，由统一构建准备；本批未复制、生成或运行 dist 文件。

当前静态改动还修正了失败重试：再次发送前读取原草稿及版本；目标有修改时先通过现有草稿更新 API 保存，且每次按当前选择确认负责人。已经执行的目标不会被改写；若旧目标其实已启动而当前文字不同，明确保留当前草稿并提示它尚未发送。审批卡片只显示当前执行轮及其子任务的待审批请求，并标出来源任务，不混入同项目其他会话的请求。对应回归用例已写入，尚未运行，不计入下文历史通过数量。

未结束的任务在等待处理或可恢复状态下也保留“停止任务”，取消仍调用既有服务端接口。完成图标仅用于已完成状态，失败与等待状态按实际状态显示。

结果预览由独立加载器管理，不等待预览结束才继续快照轮询。失败或超时按产物显示，可单独重新读取，保留下载入口；定时状态刷新不反复请求失败项。切换会话、产物 SHA-256 改变或卸载会取消过期请求；即使传输未响应取消，旧请求身份也不能覆盖当前预览。本批源码与回归用例尚未运行，不能计为通过。

历史预置定义缺失时，工作台仍加载数据库中已有的成员；首次空库只导入可读取的预置定义，也可在界面自行注册。已删除的成员不会在重启后重新创建。认证配置仍按已确认的完整启动入口匹配，无法匹配时使用成员自身默认登录环境并在界面检查状态。

历史开发实例流程示例：`http://127.0.0.1:8047/?task=task-87da23f9-eb9e-47e5-bbd3-0e10f09e1639`。当前日用任务请从 8057 工作台左侧历史打开。

### 接入和调整协作成员

打开“协作成员”，点击“接入本机协作者”：可以从产品目录选择，查找本机已安装入口；也可以粘贴启动命令或含多个成员的 `agent_servers` 配置。确认列表支持“再添加一个产品”，可一次接入多位成员。每位成员独立显示保存、连接与登录结果，失败项可以修正后继续；重复入口保留已有成员设置。高级手动配置仍可填写完整启动入口。

批量配置按“粘贴命令或导入配置文件 → 预览成员 → 接入所选成员”操作。先核对每位成员的名称、程序路径和参数，再接入；无效项会单独提示，已完成项不需要重做。JSON 文件入口在本机浏览器读取，最多 256 KB、每批 20 位成员；文件内容不会自动赋予负责人资格。重复导入保留已有成员的名称、勾选状态和进度，同名同原因的无效项也不会重复累积。选择文件不会清空输入框中尚未预览的命令。

已进入确认列表的接入草稿保存在当前浏览器标签页，刷新后通过“继续接入草稿”恢复，并重新核对服务端已有成员，避免重复注册。产品页未完成的手动路径和参数按产品分别保存，可通过“继续未完成入口”恢复；粘贴的原始命令须先加入待接入列表。含凭据特征的启动参数不缓存。产品安装仍由用户决定，此流程不会自动安装软件或复制登录凭据；环境配置只接受需要继承的变量名称。

产品手动接入、配置编辑和失败后的入口修正使用同一种参数填写方式：每个参数一个输入框，支持添加与移除。有空格的路径不需要额外引号；参数内的换行和显式空参数会保留，空白项会明确提示。产品目录建议参数可以直接填入；Node 脚本路径在产品接入表单中单独填写，不必重复加到参数列表。命令和 JSON 批量导入入口仍保留。

接入成功后，成员卡片提供“用此成员新建任务”，返回工作台后填写目标并发送，不要求负责人资格；有编排资格的成员还提供“由它安排协作”。这两个入口只选择新任务的执行方式，不发送模型提示或改变已有会话的执行者。从新任务页面打开成员卡片并选择时，已有目标草稿和工作目录选择保持不变。浏览器分别记住两种方式的成员选择。连接状态变化时保留已选成员并提示当前不可用，不会悄悄改发给另一位成员。选择记录只包含执行方式和成员 ID，不是权限或工作目录确认。

“编辑配置”的高级选项提供负责人资格、协作接口和逐项权限。要让一个成员担任负责人，需明确选择允许担任负责人、MCP 接口及“编排任务”权限；连接和登录就绪后，该成员会进入新任务的负责人列表。其他协作权限按实际需要选择，勾选负责人资格不会自动授予权限。

成员可以停用；没有历史或项目引用的停用成员可先检查移除资格，再确认移除注册。已有任务的成员保留登记与历史。执行中仍可停用或收回权限；启动配置变化和扩权由服务端阻止。保存配置后需重新检查连接状态。

启用、停用或移除后若确认响应丢失，界面先核对服务端状态，不会自动重复提交。核对成功会显示实际结果；仍无法确认时，先刷新成员状态再决定是否重试。移除仅取消未被引用的注册配置，不卸载程序、不清除产品登录状态。

### 输入与草稿恢复

左侧任务列表支持搜索任务标题、历轮目标、项目名和参与成员，空格分隔的关键词共同匹配。状态筛选可快速找到进行中、待处理、已完成、草稿和已停止的对话。“待处理”包括失败、阻塞和等待确认，以及仍有待审阅改动的已完成任务；待审阅不会把执行状态改成失败。筛选只影响左侧列表，不删除记录或打断当前会话。

新任务和各会话的追问草稿分别保存在当前标签页的浏览器缓存中，刷新后恢复。缓存被禁用或空间不足时，输入和发送仍可使用，界面会提示草稿只保留在当前页面；切换会话后返回仍能找回该页面中的最新文字，刷新或关闭前应先复制。缓存异常不会把已被服务端接收的任务误报为发送失败。任务记录仍由服务端持久保存，和未发送的浏览器草稿分开。

### 查看和合并文件改动

遇到待确认操作时，点击任务顶部“待确认”即可直接打开当前请求；提示列表的“查看并确认”分别定位对应请求，即使打开了过程面板也不必翻找聊天记录。确认窗口直接显示适配器解析出的完整命令、工作目录、操作风险与截止时间；原始请求和执行边界保留在折叠详情中。长命令可换行、选择和滚动查看，窗口底部始终保留“拒绝 / 允许本次”。Esc 关闭后焦点返回原入口。请求处理或过期后，窗口显示更新提示，不再保留允许按钮；提交失败时错误也会出现在窗口内。

“允许本次”只处理当前一项操作，不改变项目自动审批设置。工作目录不是系统安全沙箱，界面不会根据命令包含 `--check` 等字样宣称安全。工作区文件自动审批、命令与越界访问询问、人工审阅合并继续沿用既有规则。

过期请求会在原会话中保留“查看过期请求”入口，继续追问后仍可查看。历史详情保留完整命令、工作目录、截止日期与实际审批状态，不提供允许/拒绝按钮；过期未获授权与主动拒绝分别展示。Agent 回复可能将工具返回的拒绝泛称为用户拒绝，应以审批记录为准。执行已结束也不代表未获授权的检查已经通过。

本轮命令获准后，可从“查看授权记录”回看完整请求；执行状态及退出结果在“过程”中单独记录。旧轮次的过期记录默认收起到“历史过期记录”，展开后仍可查看；本轮刚过期的请求默认展开。查看记录不会重发命令或改变权限。

在任务页打开“过程”“文件改动”和“页面预览”，即可在同一工作台查看执行记录、当前工作区差异和页面效果。静态 HTML、CSS、JavaScript 文件保存后，预览会自动更新，无需生成审阅快照。需要编译或启动开发服务的项目仍按命令权限处理，不会自动安装依赖。

继续修改时直接在原会话追问。失败时先看原因，再使用原任务的重试入口；已有文件和前次记录保留，重试不是回滚。若页面提示重试确认尚未收到，后台可能已开始执行，请先看最新状态，不要反复点击。
